# PickMe

PickMe — приложение для управления приютом. Гости могут смотреть каталог, карточки животных и фотографии. Зарегистрированный пользователь после входа может добавить животное в общий каталог.

Сейчас готовы каркас Go API, запуск через Docker Compose, схема PostgreSQL и API аккаунтов. Страницы и маршруты животных ниже описывают контракт MVP.

## Быстрый запуск

Понадобится запущенный Docker с Docker Compose v2. Запустите стек из корня проекта.

```sh
docker compose up --build --wait
```

Откройте [стартовую страницу](http://localhost:8080/) или [проверку API](http://localhost:8080/api/health). При доступной БД проверка возвращает `200` и `{"status":"ok"}`. При потере связи с БД она возвращает `503`.

```sh
docker compose ps -a
docker compose logs migrate
docker compose run --rm migrate status
docker compose down
```

Эти команды показывают состояние контейнеров, журнал и статус миграций, а последняя команда останавливает стек. Данные PostgreSQL хранятся в именованном томе `postgres_data` и сохраняются после `docker compose down`.

Для локальной разработки Compose использует значения по умолчанию. Чтобы переопределить их, скопируйте `.env.example` в `.env` и измените нужные поля.

| Переменная | Назначение |
| --- | --- |
| `WEB_PORT` | Порт сайта на `127.0.0.1`, по умолчанию `8080`. |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Имя БД, пользователь и пароль для локального PostgreSQL, по умолчанию `pickme`. Применяются при создании пустого тома. |
| `DATABASE_URL` | URL подключения для Go API и Goose. В Compose по умолчанию указывает на `db:5432`, а имя БД и учётные данные передаются отдельно через `PGDATABASE`, `PGUSER` и `PGPASSWORD`. |
| `HTTP_ADDR` | Адрес прослушивания при прямом запуске Go, по умолчанию `:8080`. В контейнере установлен `:8080`. |
| `COOKIE_SECURE` | Установите `true` при работе через HTTPS, чтобы сессионная cookie отправлялась только по защищённому соединению. Для локального HTTP используется `false`. |

Для запуска `go run ./cmd/pickme` вне Compose укажите `DATABASE_URL` для доступной с хоста базы данных. Для локальной проверки Go-кода используется Go 1.26 или новее.

```sh
go test ./...
go vet ./...
```

## Архитектура

Go предоставляет HTTP API на `net/http`. Фронтенд на HTML/CSS/JS получает данные через `fetch` и выводит их на страницах. Nginx отдаёт файлы фронтенда и направляет запросы `/api/` в Go, поэтому браузер работает с одним адресом и использует сессионную cookie для API.

`cmd/pickme` читает настройки, создаёт общий `pgxpool`, проверяет соединение с БД и запускает HTTP-сервер с корректным завершением по сигналу. SQL-запросы для регистрации и животных будут в пакетах `internal/auth` и `internal/animals`. Параметры передаются в PostgreSQL отдельно от текста SQL.

| Сервис | Роль |
| --- | --- |
| `db` | PostgreSQL 17 с постоянным томом и проверкой готовности через `pg_isready`. |
| `migrate` | Дожидается готовности PostgreSQL, применяет миграции через `goose up` и завершает работу. |
| `app` | Запускается после успешных миграций и обслуживает HTTP API во внутренней сети Compose. |
| `web` | Nginx отдаёт страницы, проксирует `/api/` с исходными путём и `Host`, проверяет готовность через `/api/health`. Только этот сервис публикует порт для браузера. |

```text
cmd/pickme/          запуск и остановка Go API
internal/config/     настройки из окружения
internal/httpserver/ маршрутизация, middleware и HTTP-ответы
migrations/          версионируемые SQL-миграции Goose
web/pages/           статические HTML-страницы
web/nginx.conf       прокси к Go API и выдача страниц
Dockerfile           цели сборки Go API и Goose
compose.yaml         локальный стек
```

## Схема PostgreSQL

| Таблица | Данные и связи |
| --- | --- |
| `users` | `id`, уникальный `email`, `password_hash`, `full_name`, `created_at`. При регистрации API удаляет пробелы по краям имени и email и приводит email к нижнему регистру. `full_name` может быть `NULL` у аккаунтов, созданных до миграции. |
| `sessions` | `token_hash` (32 байта, первичный ключ), `user_id` со ссылкой на `users`, `expires_at` с индексом. При удалении пользователя его сессии удаляются каскадно. |
| `animals` | `id`, `name`, `found_location`, `breed`, `created_by` со ссылкой на `users`, `created_at`. Индекс `(created_at DESC, id DESC)` поддерживает порядок каталога от новых записей к старым. |
| `animal_photos` | `animal_id` одновременно служит первичным и внешним ключом, поэтому у животного может быть одна фотография. `content_type` допускает JPEG и PNG, `data` хранит от 1 байта до 5 МиБ в `bytea`. При удалении животного фото удаляется каскадно. |

Кличка и порода содержат от 1 до 100 символов, место обнаружения — от 1 до 255. Строки хранятся без пробелов по краям. Эти ограничения заданы в схеме, а API будет проверять поля до записи. Новое изменение схемы оформляется отдельной SQL-миграцией. Goose хранит номера применённых миграций в PostgreSQL и при повторном запуске выполняет только новые миграции.

## Страницы MVP

| URL | Действие |
| --- | --- |
| `/` | Показывает каталог животных или состояние пустого каталога. |
| `/register` | Регистрирует по email и паролю, затем открывает страницу входа. |
| `/login` | Выполняет вход и открывает каталог. |
| `/animals/new` | Показывает форму добавления после проверки сессии. Гостя направляет на вход. После сохранения открывает карточку нового животного. |
| `/animals/{id}` | Показывает кличку, породу, место обнаружения и фото или заглушку. |

Фронтенд использует `GET /api/me` для состояния меню и формы добавления. Пользователь с действующей сессией со страниц входа и регистрации возвращается в каталог. Кнопка выхода завершает текущую сессию и открывает каталог.

## Контракт API

| Метод и путь | Доступ | Успешный ответ |
| --- | --- | --- |
| `GET /api/health` | Все | `200` и состояние соединения с БД. Реализован. |
| `POST /api/register` | Гость | `201` и объект нового пользователя. Принимает `full_name`, `email` и `password`. |
| `POST /api/login` | Гость | `200`, объект пользователя и `Set-Cookie`. |
| `POST /api/logout` | Все | `204` и удаление cookie. Повторный выход даёт тот же результат. |
| `GET /api/me` | Все | `200` и объект пользователя в поле `user` или `{"user":null}` для гостя. |
| `GET /api/animals` | Все | `200` и массив животных от новых к старым. Пустой каталог возвращает `[]`. |
| `POST /api/animals` | После входа | `201`, сохранённое животное и `Location: /api/animals/{id}`. |
| `GET /api/animals/{id}` | Все | `200` и объект животного. |
| `GET /api/animals/{id}/photo` | Все | `200` и байты JPEG или PNG. |

Объект пользователя содержит `id`, `email` и `full_name`. Объект животного содержит `id`, `name`, `found_location`, `breed`, `created_at` в RFC 3339 и `photo_url`. Поле `photo_url` содержит `/api/animals/{id}/photo` или `null`. ID в JSON передаются строками, чтобы сохранить точность `bigint` в JavaScript.

Вход и регистрация принимают JSON с `email` и `password`. Для регистрации также требуется `full_name` длиной от 2 до 100 символов. Добавление принимает `FormData` с полями `name`, `found_location`, `breed` и необязательным файлом `photo`. Браузер сам формирует `Content-Type: multipart/form-data` и границу частей.

Ошибки API имеют формат `{"error":{"code":"...","message":"..."}}`. Для `422` поле `error.fields` может содержать сообщения по полям формы. Используются `400` для некорректного тела, `401` для ошибки входа или отсутствия действующей сессии на защищённом маршруте, `403` для отклонённого источника запроса, `404` для отсутствующей записи или фото и `413` для превышения размера загрузки. API возвращает `409`, если email занят или запрос входа либо регистрации пришёл с действующей сессией. При сбое БД рабочие маршруты возвращают `500` с общим сообщением. Фронтенд обрабатывает также сетевые сбои и ответы прокси без JSON.

### Пароли и сессии

- Регистрация проверяет формат email и длину пароля от 12 до 128 символов. БД гарантирует уникальность email. Пароль хранится в виде хеша Argon2id с индивидуальной случайной солью и параметрами алгоритма.
- При входе Go сверяет результат хеширования введённого пароля с сохранённым хешем. Сообщение для неверного пароля и неизвестного email одинаковое — «Неверный email или пароль».
- После входа браузер получает случайный токен из 32 байт в cookie `pickme_session`. PostgreSQL хранит SHA-256 токена. Сессия действует 24 часа. Cookie использует `HttpOnly`, `SameSite=Lax`, `Path=/api`. Для HTTPS предусмотрена настройка `COOKIE_SECURE`.
- Middleware проверяет хеш токена и срок действия. `auth.RequireUser` защищает операции записи, а `auth.CurrentUser(*http.Request) (int64, bool)` даёт Go-обработчику ID из контекста запроса. Ответы с данными сессии используют `Cache-Control: no-store`.
- Выход удаляет запись текущей сессии из PostgreSQL и очищает cookie. Общий `http.CrossOriginProtection` проверяет источник запросов, меняющих данные.

### Добавление животного

Публичные `GET`-маршруты каталога и карточек регистрируются в `ServeMux` напрямую. При подключении добавления к маршрутам API используйте `accounts`, созданный через `auth.New`, чтобы сначала проверить cookie, а затем требовать действующую сессию.

```go
mux.Handle("POST /api/animals", accounts.WithSession(auth.RequireUser(http.HandlerFunc(addAnimal))))
```

Go проверяет сессию до чтения формы и берёт `created_by` из неё. Тело формы ограничено 6 МиБ, сам файл — 5 МиБ. API определяет формат по байтам, проверяет JPEG или PNG, проверяет предел в 16 мегапикселей перед полным декодированием и удаляет временные файлы после обработки формы.

Запись в `animals` и необязательная запись в `animal_photos` сохраняются одной транзакцией. Если сохранение файла завершается ошибкой, откатывается и создание животного. В каталоге API возвращает текстовые поля и ссылку на фото. Браузер загружает байты отдельным запросом с корректным `Content-Type` и `X-Content-Type-Options: nosniff`.

## Разработка MVP

- Разработчик №1 ведёт общий Go API, Docker Compose, Nginx, всю схему PostgreSQL, регистрацию, вход, выход, middleware сессий и подключение соответствующих страниц.
- Дима ведёт API каталога, карточек, добавления и выдачи фотографий, а также страницы каталога, карточки и форму добавления.
- При интеграции проверяются запуск на чистой БД, регистрация и вход, запрет добавления для гостя, добавление с фото и без него, обработка невалидных полей или файла, выход и сохранение данных при повторном запуске Compose.
